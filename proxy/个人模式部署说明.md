# FlowCraft API 代理 · 个人自用模式部署说明

> 场景：中转站（如 momoai.asia）不支持浏览器 CORS，纯前端页面无法直连。
> 方案：部署一个 Cloudflare Worker 做转发——浏览器 → Worker（有 CORS）→ 中转站（服务器间转发，无 CORS 限制）。
> 个人模式无需 KV、无需签发 HMAC 令牌，3 个配置即可跑通。

## 一、前置条件

- 一个 Cloudflare 账号（免费版即可）
- 本机安装 Node.js 与 wrangler：`npm install -g wrangler`
- 登录：`wrangler login`

## 二、部署步骤

### 1. 创建 wrangler.toml（放在 `proxy/` 目录）

```toml
name = "flowcraft-proxy"
main = "worker.js"
compatibility_date = "2026-08-01"

[vars]
# 个人自用：放行所有来源（含 file:// 本地打开）。公开部署请改回白名单：
# PROXY_ALLOWED_ORIGINS = "https://allin-868.github.io"
PROXY_ALLOWED_ORIGINS = "*"
# 你自定义的访问口令（前端 ⚙ 里的「代理令牌」要填同一个）
PERSONAL_ACCESS_TOKEN = "改成你自己的口令"
# 上游指向中转站（openai provider 的生图/对话都会走这里）
OPENAI_UPSTREAM_BASE = "https://momoai.asia/v1"
```

### 2. 配置中转 Key（secret，不要写进 toml）

```bash
cd 输出成果/deploy/proxy
wrangler secret put OPENAI_KEY
# 按提示粘贴 momoai.asia 的 Key（sk-...）
```

### 3. 部署

```bash
wrangler deploy
```

部署成功后得到地址，形如 `https://flowcraft-proxy.<你的子域>.workers.dev`。

### 4. 验证 Worker（可选，部署后执行）

```bash
# 应返回 401 令牌无效（说明 Worker 活着、鉴权生效）
curl -i -X POST https://<你的worker地址>/proxy -H "Content-Type: application/json" -d "{}"

# 带口令应能转发到中转站（Key 错误时返回中转站自己的报错，如 401 API_KEY_REQUIRED）
curl -i -X POST https://<你的worker地址>/proxy \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <你的口令>" \
  -d "{"provider":"openai","endpoint":"/chat/completions","body":{"model":"gpt-5.4","messages":[{"role":"user","content":"hi"}]}}"
```

## 三、前端（FlowCraft）配置

1. 打开 AI 助手 → 右上角 ⚙
2. **API 代理地址**：填 `https://flowcraft-proxy.<你的子域>.workers.dev`
3. **代理令牌**：填 `PERSONAL_ACCESS_TOKEN` 里的口令
4. 点「保存/启用」

生效行为：

| 功能 | 路径 |
|---|---|
| 生图（gpt-image-2 等）/ 中转对话（GPT/Claude/Gemini/Grok） | 浏览器 → Worker → momoai.asia |
| DeepSeek V4 Flash | 已配 Key 时仍走直连（直连优先策略），不走 Worker |
| ComfyUI | 本地直连 127.0.0.1:8188，不经过 Worker |

## 四、费用与安全说明

- Cloudflare Workers 免费版每天 10 万次请求，个人使用绰绰有余。
- Key 只存在 Worker secret 里，浏览器与前端代码中都不会出现。
- `PROXY_ALLOWED_ORIGINS = "*"` + 固定口令适合单人自用；若日后公开分享页面，请改回来源白名单并考虑换回 HMAC 令牌模式（worker.js 保留了完整生产逻辑）。
- momoai 的计费由中转站按其自身规则扣除。

## 五、常见问题

- **前端报「代理转发失败（代理：…）」**：说明 Worker 地址填错或 Worker 未部署成功，用第四节 curl 验证。
- **Worker 返回「provider openai 未配置上游地址」**：`OPENAI_UPSTREAM_BASE` 未配置或拼写错误。
- **转发成功但中转站报 401**：`OPENAI_KEY` secret 配置的不是该中转站的 Key。
- **想同时用官方 DeepSeek**：给 Worker 配 `DEEPSEEK_KEY` secret 即可（前端无 Key 时 DeepSeek 会自动走 Worker）。
